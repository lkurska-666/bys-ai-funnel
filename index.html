BYS AI funnel

Everything clickable, in one place. The two prototypes run the whole flow; the rest hold a single moment still so it can be looked at without playing through to reach it.

The funnel — responsive

The one to open. Nine steps end to end, and the layout switches between desktop and mobile with the width of the window — drag the edge, or use the device toolbar in dev tools. The switches for the failure states are in the nav, and behind the Prototype button once the window is narrow.

Desktop only

The desktop file as it stood before the merge, kept so there is something to compare against. Nine steps end to end, with switches in the nav for the failure states — publish fails, build fails, the offer countdown at 10 seconds, a suggested domain already taken.

Mobile only

The mobile file as it stood before the merge, kept for the same reason. 390×844 in a phone frame that scales to your window — the frame and its status bar are the mockup, and do not exist in the responsive file. Answers hang off the right edge, the progress ring sits bottom-left, a focused field lifts clear of the keyboard.

Coming back later

What a merchant sees when they leave and return — before the build, after the build, and the checklist that replaces production’s list of ten steps. Coming back is not the same as going back.

A finished step, opened

Clicking a finished step opens it in place: what was chosen, and whether it is still yours to change. The switch at the top is the question for the developers, made clickable.

Domain — the failure states

All four states of a domain that turns out to be taken, held still: a failed suggestion, the retry block, a typed name that fails, and the error on the row itself.
